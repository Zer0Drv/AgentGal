<goal>
请把材料整理成当前记忆对象的长期记忆事件。

目标：得到边界清楚、可稳定召回的事件块。优先保留一段经历的完整互动弧线，不要把连续推进的一场互动切成很多碎块。
</goal>

<inputs>
- <memory_owner>：说明"我 / 玩家 / 其他角色"分别是谁。输出始终写成当前记忆对象视角。
- <memory_entries>：告诉你哪些事实、理解、在意点需要保留，但它现在的分块不一定正确。
- <raw_dialogue>：提供可观察事实、顺序、动作、台词和场景切换，用来判断边界。旁白里的"你 / 你家 / 你这边"默认指玩家一侧。
</inputs>

<rules>
- 先统一视角再写结果：当前记忆对象写成"我"，不要保留"玩家 / 实名 / 你家"这类材料标签。
- 事实顺序、动作、谁说了什么，以 <raw_dialogue> 为准；<memory_entries> 中不冲突的理解和感受要自然吸收进去。
- 不要机械沿用 <memory_entries> 现有分块；必要时重组、合并或拆开。
- 分块时默认先看能不能合并：只要前后仍在推进同一个互动目的、同一段关系推进，哪怕只隔几分钟、换了站位、走到相邻地点、出现几次试探或回应，通常仍是一条。
- 只有前一段已经形成相对完整的结果，后面又开启新的目标、新的冲突、新的场景或新的在场组合时，才拆成下一条。
- 尤其不要按"一句话 / 一个动作 / 一次试探 / 几分钟时间点"切块；如果几块彼此依赖，合起来更像完整事件，就应该合并。
- 以事实为主，保留关键动作、原话、转折、边界、承诺、误会、确认和关系推进；感受只保留解释其重要性的部分，不要长篇心理分析。
- 时间字段要能看出属于哪一天；连续时段可写范围。地点可写同一连续互动经过的相邻地点，不必为字段整齐把一场经历拆碎。
- 写完后再检查一次：有没有把同一场连续互动拆碎，或把真正独立的事件硬并在一起。
- content 字段不要换行，一行写完全部内容。
</rules>

<output_format>
以 JSON 格式输出 events 数组。每个事件对象包含 date、time、location、participants、content 五个字段（content 不要换行，一行写完）：

{{"events": [
  {{"date": "X月X日", "time": "时间段", "location": "地点", "participants": "在场人物", "content": "事件内容（一行，不换行）"}},
  ...
]}}
</output_format>
